## 1. MD Format Contract

The Markdown file generated by `generateBriefMarkdown()` must be parseable back into structured data.

### Current export format

```markdown
# Discovery Técnico — Center Móveis

**Status:** Em progresso
**Criado em:** 15/06/2026

---

## Estratégico
*Entregável:* Responsáveis pelo projeto definidos...

### Quem será o responsável técnico? *
**Orientação:** Ponto focal para integração, acessos, TI.

> Adolfo Fernandes, gestaosistemas@centermoveiseeletros.com.br

*Por Jorge Carvalho · 16/06/2026*

### Pergunta sem resposta

*Sem resposta*
```

### Parser contract

`parseBriefMD(md, sections, existingResponses)` must:

1. **Split by `## `** — H2 = section. Match by `section.title` (normalized: trim, lowercase).
2. **Within section, split by `### `** — H3 = question. Match by `question.text` (normalized: trim, lowercase, strip trailing ` *`).
3. **Extract response** — first `> ` blockquote after H3 that is NOT preceded by `**Orientação:**`. If no blockquote, check for `*Sem resposta*` marker.
4. **Ignore metadata** — `**Status:**`, `**Criado em:**`, `---`.
5. **Discard unmatched** — log to console.warn, skip.

### Normalization

```js
function normalize(str) {
  return str.replace(/\s+/g, ' ').replace(/ \*$/, '').trim().toLowerCase()
}
```

### Edge cases

| Situation | Behavior |
|---|---|
| Question text ends with `*` | Strip trailing ` *` before comparing |
| Multiple `> ` blockquotes in a row | Take first one NOT after `**Orientação:**` |
| No `> ` and no `*Sem resposta*` | Treat as empty response |
| Section/question not found | Warn and skip |
| Extra questions in MD not in structure | Warn and skip |
| Structure questions not in MD | Leave unchanged |
| Response with newlines | Preserve from blockquote |

## 2. UI Design

### 2.1 Rail — "Última atualização" + Upload button

```
┌──────────────────────────┐
│  📥 Última atualização   │ ← relative time from responses
│  5 min atrás             │
├──────────────────────────┤
│  [⬆ Upload respostas]   │ ← new button
│  [⬇ Baixar MD]          │ ← existing
└──────────────────────────┘
```

**Upload button:** Same visual style as "Baixar MD". Uses `Icons.Upload`. Opens file picker on click.

### 2.2 File Picker

Hidden `<input type="file" accept=".md,text/markdown">`. Click on upload button triggers it. `onChange` reads file via `FileReader.readAsText()` and passes to parser.

### 2.4 Confirm → Bulk Upsert

Batch all matches in a single Supabase call:

```js
supabase.from('brief_responses').upsert(rows, {
  onConflict: 'instance_id,question_id',
})
```

On success: toast, invalidate `['brief_responses', instance.id]`, close preview.
On error: toast with error message.

## 3. Data Flow

```
CSM → click "Upload respostas"
  → hidden <input type="file"> opens
  → select .md file
  → FileReader.readAsText()
  → parseBriefMD(md, sections, responses.data)
  → if no matches: toast.warn("Nenhuma resposta reconhecida")
  → if matches: show preview modal
    → CSM reviews diff
    → click "Confirmar upload"
    → supabase.from('brief_responses').upsert(matches)
    → toast.success / toast.error
    → invalidateQueries(['brief_responses', instance.id])
    → close preview
```

## 5. Current Checkpoint

### Production state

- BriefResponsesModal has "Baixar MD" working
- No upload in UI
- Standalone CLI script exists (`scripts/upload-brief-responses.js`) for one-off uploads

### Architectural decisions

| Decision | Rationale |
|---|---|
| MD round-trip, not JSON | CSM já edita o MD manualmente. Round-trip natural sem novo formato. |
| Match by question text, not ID | MD export é formato humano. Match por texto normalizado é a única opção. |
| Bulk upsert em 1 chamada | Menos latência, estado consistente (tudo ou nada). |
| Preview modal antes de upsert | CSM precisa ver diff antes de sobrescrever respostas. |
| Parser como função pura | Testável isoladamente, sem dependência React/Supabase. |
