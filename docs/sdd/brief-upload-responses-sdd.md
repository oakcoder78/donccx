## 1. Format Contracts

### 1.1 Markdown (MD)

Same format generated by `generateBriefMarkdown()`:

```markdown
# Discovery Técnico — Center Móveis

**Status:** Em progresso

---

## Estratégico

### Quem será o responsável técnico? *
**Orientação:** Ponto focal para integração, acessos, TI.

> Adolfo Fernandes

*Por Jorge Carvalho · 16/06/2026*
```

#### Parser: `parseBriefMD(md, sections)`

1. Split by `## ` → H2 = section. Match by `section.title` (normalized).
2. Within section, split by `### ` → H3 = question. Match by `question.text` (normalized, strip trailing ` *`).
3. Extract response from `> ` blockquotes after H3, ignoring blockquotes after `**Orientação:**`.
4. Discard unmatched sections/questions (returned as warnings).

### 1.2 JSON

```json
{
  "responses": [
    { "question_id": "uuid-here", "response_text": "Adolfo Fernandes" }
  ]
}
```

#### Parser: `parseJSON(text, sections)`

1. Parse JSON, accept either `{ responses: [...] }` or bare array.
2. Match each item by `question_id` against all questions in structure.
3. Missing `question_id` or unmatched → warning.

## 3. Data Flow

```
CSM → click "Importar respostas"
  → hidden <input type="file" accept=".md,.json"> opens
  → select file
  → FileReader.readAsText()
  → parseUploadFile(text, fileName, structure)
    → .md  → parseBriefMD()
    → .json → parseJSON()
  → if no matches: toast.warn
  → if matches: show preview modal with diff
    → CSM reviews
    → click "Importar X resposta(s)"
    → uploadResponses.mutate(matches)
    → supabase.from('brief_responses').upsert(rows, { onConflict: 'instance_id,question_id' })
    → toast.success + invalidateQueries(['brief_responses', instance.id]) + close preview
```

## 5. Architectural Decisions

| Decision | Rationale |
|---|---|
| MD round-trip + JSON | CSM edits MD manually; JSON for programmatic/CLI use |
| Match by normalized text (MD) | MD export is human-readable, no IDs |
| Match by question_id (JSON) | Precise, no ambiguity |
| Bulk upsert in 1 call | Less latency, atomic |
| Preview modal before upsert | CSM needs to see diff before overwriting |
| Parsers as pure functions | Testable without React/Supabase |
| Always upsert (never skip) | Simpler UX — single confirm button |

## 6. Gotchas

- **Icons:** never import from `lucide-react` directly. Use `src/lib/icons.js`.
- **Query invalidation:** `qc.invalidateQueries({ queryKey: ['brief_responses', instance.id] })` — must be object form.
- **Response column:** `response_text`, not `answer`.
- **Upsert key:** `onConflict: 'instance_id,question_id'`.
- **responded_by_email:** Hardcoded as `'csm'` for uploads.
